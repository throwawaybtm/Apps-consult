# PRD checklist

Language: **Indonesian** (technical terms such as API, login and dashboard stay untranslated). Target length: about **3–5 pages**. The client approves the PRD before anything else.

- [ ] **Problem and goals:** the client's problem in plain words, and what success looks like for them.
- [ ] **Users:** who uses the app (roles or groups) and what each one needs from it.
- [ ] **Features:** a numbered list (F1, F2, …). These numbers are reused in the guidebook, dev handbook and agent kit.
- [ ] **Requirements per feature:** what each feature must do, specific enough to build from.
- [ ] **Out of scope:** what is explicitly not included, so nobody assumes it is.
- [ ] **Acceptance criteria per feature:** testable statements ("Given … when … then …") that decide when a feature is done.
- [ ] **Success measures:** how the client will judge the app after launch (numbers where possible).
- [ ] **Constraints:** budget level, timeline, platforms and devices, legal or data rules, and the free-first preference.
- [ ] **Open questions:** anything still undecided, with who answers it.
- [ ] **Approval:** the client's name, role, date and sign-off.
